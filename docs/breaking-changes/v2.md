# v2 breaking changes and fork migration notes

> [!NOTE]
> These notes describe the breaking changes introduced in **v2.x.x** of the base app and assume the fork is on the **latest v1 release**. Earlier v1 changes are outside this document's scope; forks on older v1 versions also need to review the [changelog](../../CHANGELOG.md).

The main breaking changes were released in [v2.0.0](../../CHANGELOG.md#200--2025-08-05). Later v2 releases also changed application APIs and build/server behavior that fork customizations may depend on; those changes are identified separately below.

Paths and commands in this document refer to the v2 source layout. The [fork update workflow](../DEPLOYMENT.md#updating-from-the-base-app-digital-edition-frontend-ng) syncs with the current upstream `main`, so a fork merging newer releases must also review the [v3](v3.md) and [v4](v4.md) notes and use the target version's runtime requirements, file layout, and commands.

## 1. Update the runtime and merge dependencies

v2.0.0 drops Node.js 18 support. Its supported Node.js range is `^20.19.0 || ^22.12.0 || ^24.0.0`, and the supplied build infrastructure moves to Node 22. Align local development, Docker build images, and custom CI with the release being merged. Later releases have stricter requirements; the v2 range is historical guidance, not the requirement for current `main`.

v2.0.0 moves to Angular 20 and Express 5. Merge `package.json` and `package-lock.json` together, preserving the edition's package identity and custom scripts while adopting the upstream dependency changes. Run `npm ci` after resolving them. Browser support is aligned with Angular 20; test the edition in the browsers supported by the target Angular release.

Forks with a customized root `server.ts` must merge the Express 5-compatible middleware changes. The upstream server replaces old wildcard registrations such as `server.get('*', ...)` and `server.get('*.*', ...)` with middleware and static-file handling. Preserve the ordering of static serving, missing-file handling, and Angular rendering when adapting custom routes.

`@angular/platform-browser-dynamic` is removed. Custom browser bootstrap or test initialization code importing it must adopt the corresponding `@angular/platform-browser` APIs used by the target source. This v2 change still uses an NgModule-based application; the standalone bootstrap arrives in v3.1.

## 2. Merge the Sass inclusion changes

The shared stylesheet structure changes from Sass `@import` to `@use` and `meta.load-css()`. Forks that commented out imports in `src/global.scss` must reapply their selections to the new structure instead of retaining the old file wholesale.

| Customization | v2 location and mechanism |
| --- | --- |
| Select bundled fonts. | `src/global.scss`: comment out unused `meta.load-css()` calls. |
| Select individual TEI features. | `src/theme/_inc-global-tei.scss`: comment out unused `@use` lines. |
| Select info-overlay and tooltip styles. | `src/theme/_inc-global-optional.scss`: comment out unused `@use` lines. |
| Add edition-specific CSS or override CSS variables. | `src/assets/custom_css/custom.scss`. |

For example, font selection in `src/global.scss` becomes:

```scss
@use "sass:meta";

@include meta.load-css("theme/font-face/roboto");
@include meta.load-css("theme/font-face/source-serif");
// @include meta.load-css("theme/font-face/mulish");
// @include meta.load-css("theme/font-face/inter");
```

Keep the edition's actual font choices. The new shared bundles also reorganize general, Markdown, and miscellaneous styles; use the upstream inclusion structure and carry over any deliberate fork overrides. Custom Sass partials must declare their own `@use` dependencies rather than relying on variables becoming globally available through `@import`.

The `.teiComment.noteReference` rule is removed from `src/theme/TEI/_tei-comments.scss`. Editions that need the previous appearance of references after comment notes can add this rule to their `custom.scss`:

```scss
div.tei .teiComment.noteReference {
  display: block;
  font-size: 0.85em;
  line-height: 1.55;
  margin-top: 0.5em;
}
```

The [theming guide](../THEMING.md) explains the current styling extension points. Its filenames reflect the newer layout; the corresponding v2 names are listed above.

## 3. Reconcile navigation settings and branding

The top menu now contains the translated site title linked to the home page. Its separate home button, right-hand site logo, and "refer to edition" button are removed. Check `Site.Title` in the edition's translation files, since it is now visible in this additional location.

Remove these obsolete configuration entries when merging `src/assets/config/config.ts`:

| Removed setting | v2 behavior and fork action |
| --- | --- |
| `component.topMenu.showSiteLogo` | The right-hand logo is no longer shown. Review branding that depended on it. |
| `component.topMenu.siteLogoDefaultImageURL` | Remove the unused logo URL. Keep the image if another part of the edition uses it. |
| `component.topMenu.siteLogoMobileImageURL` | Remove the unused mobile logo URL. |
| `component.topMenu.siteLogoLinkURL` | The site-title link leads to the app's home page. |
| `component.topMenu.siteLogoDimensions` | Remove the unused logo dimensions. |
| `component.topMenu.showURNButton` | The top-menu reference button is no longer available. Review any fork template or CSS targeting it. |
| `component.mainSideMenu.items.home` | Home is always present in the main side menu. |
| `component.epub` | The integrated EPUB viewer and its controls are removed. |

The new `component.mainSideMenu.items.search` flag controls the search item in the main side menu. Choose its value for the edition instead of adopting the base app's example blindly. Preserve the fork's other menu settings, translations, and links, and check the revised spacing on small screens.

## 4. Adapt ebook links and remove EPUB-viewer assumptions

The integrated EPUB viewer is removed. Integrated PDF viewing remains supported. Review the edition's `ebooks` configuration, menu entries, templates, and links for EPUB routes. If the edition still offers EPUB files, expose them as ordinary download links or download options rather than links to the removed viewer.

The ebook route format changes:

| Previous URL | v2 URL |
| --- | --- |
| `/ebook/volume.pdf` | `/ebook/pdf/volume` |

The new format puts the extension before the filename and omits the extension from the final path segment. The configured ebook `filename` still includes it, for example `volume.pdf`; do not strip it from the configuration. Keep any locale prefix on public links.

The application redirects requests using the old route format. Update fork-generated links and test existing bookmarks against the deployed server. Do not assume the redirect is an HTTP 301: the legacy route is handled by the Angular page's navigation logic.

## 5. Review later v2 changes that affect custom forks

These changes were introduced after v2.0.0. Some are optional features or internal refactors, but forks that modified the affected code or build scripts need to reconcile them.

| Release | Change and fork action |
| --- | --- |
| [v2.2.0](../../CHANGELOG.md#220--2025-09-19), with further changes in v2.4/v2.5 | Components adopt `inject()`, signal inputs and queries, `output()`, and signal-based state. Update custom TypeScript, templates, and specs to the new APIs: read signal values by calling them, and preserve readonly inputs instead of assigning to them. Review constructor and model-file changes where the fork imports or extends upstream code. |
| [v2.2.2](../../CHANGELOG.md#222--2025-11-11) | The base `extra_hosts` entry is removed from `compose.yml`. Preserve any host mappings the fork's deployment actually needs when resolving this change. |
| [v2.5.0](../../CHANGELOG.md#250--2026-02-20) | `src/app/app.routes.ts` becomes the canonical route source for production route generation. Preserve custom routes there and merge the `generate-routes` step and production file replacement. The generated file must exist even when feature filtering is disabled; do not maintain custom routes only in `app.routes.generated.ts`. |
| [v2.5.0](../../CHANGELOG.md#250--2026-02-20) | Browser route preloading defaults to idle-if-fast, while SSR preloading is disabled. Platform-specific navigation, route-state, and query-parameter services replace some direct router interactions. Merge their providers and adapt custom code or tests that relied on the former service behavior. |
| [v2.5.1](../../CHANGELOG.md#251--2026-02-27) and [v2.7.6](../../CHANGELOG.md#276--2026-06-23) | SSR adds host validation and fixes public HTTPS origins behind an internal HTTP proxy. Keep `app.siteURLOrigin` correct for the edition, and verify canonical/Open Graph URLs through the deployed proxy chain after merging custom server changes. |
| [v2.6.0](../../CHANGELOG.md#260--2026-03-12) | `ng-extract-i18n-merge` moves to v3. Remove `projects.app.architect.extract-i18n.configurations` from `angular.json`, retain the edition's translation targets, and merge the extraction options. |
| [v2.6.0](../../CHANGELOG.md#260--2026-03-12) | Dynamic SSR gains rate limiting and `app.ssr.trustProxyHops` (default `2`). Forks with custom Express middleware must preserve the limiter's placement and review the hop count for their actual proxy chain. Static responses should continue to bypass rendering and its limiter. |
| [v2.6.0](../../CHANGELOG.md#260--2026-03-12) through [v2.7.0](../../CHANGELOG.md#270--2026-05-22) | Optional authentication adds guards, token/session validation, protected-route CSR handling, and sitemap exclusions. Auth remains disabled by default. Forks enabling it must merge the supporting services, interceptor, routes, generators, and server behavior together and verify the backend `/session/validate` contract. See [authentication](../AUTHENTICATION.md). |
| [v2.7.7](../../CHANGELOG.md#277--2026-08-11) | The base app removes `@angular/animations`. Review custom code importing its APIs and adapt its animation implementation or dependency requirements to the target application. |

v2.5 also introduces legal-page configuration, and v2.7 broadens publication metadata support. These additions do not require every fork to enable new features. Preserve the edition's existing feature choices and backend contract when merging the expanded configuration.

## 6. Validate the edition after merging

Use the commands and infrastructure of the target release. For a later v2 checkout, the main checks are:

1. Install the merged dependencies with `npm ci` and run the available unit tests. Check custom component inputs, queries, and signal-based state.
2. Run `npm run extract-i18n`; confirm the edition's locale files and existing translations are retained.
3. Regenerate routes with `npm run generate-routes`, build with `npm run build:ssr`, and start with `npm run serve:ssr`. Verify custom routes in production, including routes retained when feature filtering is disabled.
4. Check fonts, selected TEI features, info overlays/tooltips, comment references, menu branding, and narrow-screen navigation.
5. Check PDF viewing, download links, and old/new ebook routes with each configured locale. Confirm there are no remaining menu links to the removed EPUB viewer.
6. Test the deployed Docker/nginx setup, canonical HTTPS URLs, static assets, and any auth-enabled routes. Run the SSR smoke checks available in the target version, using edition-specific routes and expected content.

For current file locations and edition settings, use [project customization](../PROJECT-CUSTOMIZATION.md). For newer upstream changes, continue reviewing the [v3](v3.md) and [v4](v4.md) notes as part of the same merge; this document does not prescribe installing intermediate releases.
